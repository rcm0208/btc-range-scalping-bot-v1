# Nonces and API wallets（運用で必要な部分のみ）

## ポイント
- APIウォレット（agent）は署名専用。口座照会は必ず実アドレスを指定する。
- APIウォレットは登録解除/期限切れ/残高枯渇でpruneされる可能性があるため、再利用より新規生成を推奨。prune後は過去nonceが消えるためリプレイリスクが生じる。
- 非CEX方式: 過去100個のnonceを記録。新しいnonceは「最小保存nonceより大きく、未使用」で、ブロック時刻Tに対し `(T-2日, T+1日)` の範囲。
- 署名者ごとにnonce管理される（マスター鍵かAPIウォレット）。同じAPIウォレットで複数サブアカウントを署名するとnonceを共有するので衝突に注意。

## 運用指針（Bot向け）
1. プロセスごとにAPIウォレットを分ける（サブアカウントを分離するならウォレットも分ける）。
2. バッチャを設け、0.1s間隔などで注文/キャンセルをまとめて送る。ALOバッチを分けると優先されやすい。
3. nonceは原子的カウンタで管理し、足りなくなれば現行UNIX msに早送りして衝突回避。
4. 長期運用ではAPIウォレットの有効性を定期確認し、必要に応じて再発行する。
