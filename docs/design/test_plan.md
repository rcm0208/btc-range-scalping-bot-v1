# テスト計画（ドラフト）

ここに Unit / Integration / E2E(BT) / Live最小ロット検証 のテストケース方針を記載する。

## カバレッジ案（暫定）
- Unit: indicator_engine（各指標計算）、strategy_core（レジーム/エントリー/決済判定）、risk_manager（制限判定）、broker_clientシリアライズ/署名ラッパの単体チェック（実送信なし）。
- Integration: strategy_core + backtester でダミー価格系列を用いたシグナル→約定→P&Lの流れを検証。data_providerリプレイで1m/15m同期確認。
- E2E (BT): 実データリプレイで勝率/PF/DDが算出されること。パラメータセット別の比較。
- Live最小ロット検証: 本番環境で極小ロット発注→即キャンセル、約定/通知/ログを確認（デモなし方針）。
- 例外系: レートリミット・APIエラー時のリトライ/サーキットブレーカ、WS切断再接続。緊急停止フラグの動作確認を含める。

## 具体テストケース（案）
### Unit
- indicator_engine: VWAP/BB/RSI/ADX/EMA/ATR の既知系列で期待値一致。NaN/Inf入力時の処理。
- strategy_core: レジーム判定（ADX/BB幅/EMA平行/乖離）、エントリー判定（VWAP乖離/RSI/BBタッチ/反転足）、決済条件（TP/SL/時間切れ）。
- risk_manager: cooldown/連敗/日次損失/同時ポジの判定、on_closeでの状態遷移。
- broker_client: order/cancelのペイロード生成と署名ラッパのシリアライズ（実送信はモック）。

### Integration
- 1m/15m同期: data_providerリプレイで15m確定時にレジーム更新されること。
- シグナル→約定→P&L: ダミー価格系列でTP/SL/時間切れが発火、リスク制限でブロックされること。
- 通知: notifierが bt/live ラベル付きで送信すること（モックで検証）。

### E2E (BT)
- 実データ期間（例: 1ヶ月）で勝率/PF/DDが算出され、パラメータセット間で比較可能。
- 欠損バーやデータ異常がある場合にログ警告が出て継続すること。

### Live最小ロット
- 本番で極小ロットを発注→即キャンセル。orderStatus/WS約定を受信し、ログ/Slack通知が発火すること。
- レートリミットに抵触しないこと、失敗時のリトライが動作すること。
- 緊急停止フラグ ON 時に新規エントリーを止められること。

### 例外系
- レートリミット/429/5xxでバックオフすること、上限回数超過で諦めること。
- WS切断→再接続→購読再送で正常復帰すること。
- 署名失敗時に適切なエラーを返すこと。

## データセット
- BT用: Hyperliquid公式APIで取得した1m/15mのParquet（欠損の少ない期間を選定）。欠損があれば期間を明記。
- ダミー: 単調増減・レンジ・急騰急落の合成系列を用意し、条件分岐を網羅。

## 成功判定基準
- Unit/Integration: 期待値に一致しテストが通ること。
- BT: メトリクス算出が完了すること（数値の良し悪しは別途評価）。
- Live最小ロット: 約定/キャンセルが成功し、通知・ログが出ること（収益性は不問）。
