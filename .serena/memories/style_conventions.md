# コーディング規約・命名
- PEP8 準拠、インデント4スペース。関数/変数=snake_case、クラス=PascalCase、定数=全大文字。意味のある名前を付ける。
- 型ヒント必須。外部 API 応答など構造は TypedDict/pydantic 等で明示。
- コメントは「なぜ」を説明。Broken Windows 防止で小さな問題も修正。
- ログ: 情報価値を意識し、シンボル/タイムフレーム/価格などコンテキストを含める。秘密情報はマスク。構造化 JSON ログ想定。
- エラーハンドリング: 根本原因を修正。@ts-ignore 等で握りつぶさない。外部 API 失敗を考慮し、タイムアウト/リトライ/サーキットブレーカを設計。
- セキュリティ: API キー等は .env で管理、最小権限。外部入力を検証し、不要依存を避ける。
- DRY/一貫性重視。未使用コードは削除。依存はロックファイル込みで管理。
- ドキュメント同期: README・docs/requirements.md・docs/basic_design.md をソースオブトゥルースとして更新。
- Git: コンベンショナルコミット（feat/fix/docs/test/refactor/chore）。1コミット1トピック。main 直コミットは避ける。
- テスト方針: 正常/境界/失敗を網羅（レンジ判定境界、VWAP 乖離、連敗ストップなどテーブルテスト）。テスト間依存を避け高速に保つ。
